Steps 1–3: the app never ran, so there are no app logs. Use kubectl describe pod and read Events at the bottom.
Steps 4–5: the app ran, so the logs tell the story.

The three commands

kubectl get pods -o wide

See the status. NODE shows <none> if the pod was never scheduled.

kubectl describe pod <name>

Events at the bottom show what the cluster tried and why it failed.

kubectl logs <name> --previous

What the app printed before it crashed (the container that already died).

The wait doubles each time, up to a 5-minute cap. If the container then runs fine for 10 minutes, it resets to 10s.
