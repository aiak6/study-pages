Start

Starting Codex: where, and from which folder

  • Three ways in, same agent, same login: the terminal (codex), the ChatGPT app → Codex tab, or Codex Cloud on the web, which runs on OpenAI's servers instead of my Mac.
  • Always start from a project folder, never ~. The agent can reach the folder I start it in and everything under it. Starting from home exposes all my files.
  • My folders:
    • Project X work → ~/DevOps/projectx (all 4 repos side by side) or one repo inside it
    • Old Claude history → ~/DevOps/claude-export
    • Other class work → its own folder under ~/DevOps
cd ~/DevOps/projectx && codex          # chat in the terminal
codex -C ~/DevOps/projectx             # same thing, without cd
codex "explain the infra repo README"  # start the chat with a first message

Agentic AI loves file systems. Clone the repo locally instead of pasting a GitHub link. It reads files instantly instead of going through the internet every time (Project X Session 02).

Terminal

Terminal commands (outside the chat)

codex exec "question"              # one-off answer, then exits (alias: codex e)
codex exec -s read-only "..."      # one-off, can't change anything
codex resume                       # pick an old chat to continue
codex resume --last                # continue the most recent chat
codex fork --last                  # copy a chat and try a different direction
codex review                       # code review of my changes, no chat
codex apply                        # apply Codex's last diff with git apply
codex -i screenshot.png "what's this error?"   # send an image
codex login status                 # which account
codex doctor                       # diagnose install / login / config
codex update                       # update Codex

codex exec is how Claude Code talks to Codex for me: it sends a question and reads the answer.

Safety

Sandbox & approvals: what Codex may touch

FlagValueMeaning
-s sandboxread-onlyLook, don't touch. Best for "explain this repo"
-s sandboxworkspace-writeEdit files inside the folder I started in. The normal mode
-s sandboxdanger-full-accessAnything on my Mac. Don't use it
-a approvalson-requestCodex decides when to ask me first
-a approvalsneverNever asks; failures just come back. Only for read-only or throwaway work

Approve

  • git commit / git push to my own repos
  • Installing a package I asked for
  • Running tests

Stop and ask why

  • rm -rf
  • terraform apply / destroy
  • Anything touching prod
  • aws … delete, changing IAM
When I don't know the system: ask it to explain first, have a second model (Claude) review, and try the change in dev, where it's cheap to undo.

Multi-model review: let Codex do the work, then ask Claude Code to review it, or the other way around. The comparison is itself interview material.

Cost

Usage limits & cost

Codex shows usage LEFT

80% in Codex = 80% left.

Claude shows usage USED

80% in Claude ≈ 20% left.

  • Every message spends from the same limit, chat too. Start a /new chat for a new topic instead of one giant chat.
  • Simple lookups ("which README mentions dev?") → low effort or a smaller model. Save high effort for real reasoning.
  • At work this is real money: companies over ~150 users pay per token, so model choice is a cost decision.
  • Burned through limits fast? Ask a new Codex session: "look at my usage history and tell me what used the most."
Practice

Prompts to try (Project X)

"Read the company repo README and requests/PX-001. In simple words: what is the company, who is Nadia, and what does 'deploy PR #1 to dev' mean? Don't change files."

"Explain Nadia's ECS Fargate setup in the infra repo to me as a Kubernetes person. Map each piece to its Kubernetes equivalent."

"Using the platform repo, run the app locally with Docker and tell me the URL. Explain each command before you run it."

"Look in ~/DevOps/claude-export/chats and find what I learned about ALB health checks. Give me 5 bullets."

"Give me a STAR answer for 'tell me about a time you deployed a change', based on PR #1. Only claim what I can explain."

The golden rule: start from the right folder, give Codex the situation and the context before the action, approve only what you understand, and write anything lasting into the shared notes so Claude Code knows it too.
