Build & run your image

Dockerfile → image → container, the right way for the cluster.

  • docker build -t hello:v1 .

    Build an image name:tag; . = the build context (this folder)

    S02
  • docker build --platform linux/amd64 -t investment-app:v1 .

    Build for the cluster's processor (Mac = arm64, nodes = amd64)

    S03
  • docker image inspect <image> --format '{{.Os}}/{{.Architecture}}'

    Must print linux/amd64 before every push

    S03
  • uname -m

    Your processor: arm64 or x86_64 (amd64)

    S03
  • docker history <image>

    The image's layers (a deleted secret still shows here)

    S02
  • docker run -d -p 127.0.0.1:8000:8080 --name hello hello:v1

    Laptop 8000 → container 8080, this laptop only

    S02
  • docker run -d ... --env-file investment-app.env investment-app

    Pass config at run time, not in the image

    S02
  • curl --retry 5 --retry-all-errors --retry-delay 1 localhost:8000

    Keep trying until the app answers

    S02
  • export REVISED_IMAGE=<account>.dkr.ecr.<region>.amazonaws.com/<repo>:<tag>

    Save the full image address in a variable

    S13
  • docker build --platform linux/amd64 -t "$REVISED_IMAGE" app/ && docker push "$REVISED_IMAGE"

    Build + push using the variable. Keep the double quotes or nothing gets tagged

    S13

  • kubectl get deploy,pods,svc -o wide

    S11
  • kubectl top pods -l app=investment-app

    Current CPU (m) and memory (Mi) per pod. A snapshot, not a history

    S11
  • kubectl describe pods -l app=investment-app

    Last State: Terminated, Reason: OOMKilled · FailedScheduling reason

    S11
  • kubectl patch deployment investment-app --type=strategic --patch-file investment-app-resources.patch.yaml

    Add requests/limits to the live Deployment. Changes the cluster, not your file

    S12
  • kubectl rollout status deployment/investment-app --timeout=120s

  • kubectl get limitrange -o yaml

    S12
  • kubectl get pods -l app=investment-app -o yaml
